Style Override Testing

<fc-button> renders its <button> inside a shadow root, so the two candidate override mechanisms behave very differently. Each case below is measured automatically against the real rendered button, and the verdict table at the bottom reports what actually took effect.

Heads up: the inline style attribute is the documented approach for the <finderconnect> map element, but <fc-button> reads its styles from a child <style> element instead. Cases A and B test both so the deployed page proves which one works.
Control — no overrides

Baseline default appearance to compare every other case against.

Case A1 — inline style attribute (non-inherited properties)

Sets background, border, radius and padding directly on the host element. 

<fc-button style="background: #e8590c; border: 2px dashed #862e9c;
            border-radius: 999px; padding: 14px 28px;"></fc-button>
Case A2 — inline style attribute (inherited properties)

Sets font-family and color on the host. Inherited properties can cross the shadow boundary, but only where the inner button does not set them itself. 

<fc-button style="font-family: Georgia, serif; color: #c92a2a; font-size: 20px;"></fc-button>
Case B1 — child <style> element (full restyle)

The child <style> replaces the component's entire default stylesheet, so it must declare every property it needs. 

<fc-button ...>
  <style>
    button { background: #2b8a3e; border-radius: 999px; text-transform: uppercase; ... }
  </style>
</fc-button>
Case B2 — child <style> element (outline variant with states)

Confirms that pseudo-class rules such as :hover and :focus-visible also survive inside the shadow root. Hover the button to check the transition. 

<fc-button ...>
  <style>
    button { background: transparent; border: 2px solid #1b75bb; color: #1b75bb; ... }
    button:hover { background: #1b75bb; color: #ffffff; }
    button:focus-visible { outline: 3px solid #f59f00; }
  </style>
</fc-button>
Style leak canary

The child <style> elements stay in the light DOM, so they also remain live document stylesheets. Their bare button selector can therefore match ordinary page buttons too. This check measures a freshly created unstyled <button>, which keeps the result independent of Bootstrap's own .btn rules.

What's Being Tested
  • URL parameter extraction
  • Attribution data capture (UTM params, click IDs)
  • finderCONNECT button binding via <fc-button>

  • Automatic SDK handling of booking flow
  • Style overrides via the inline style attribute versus a child <style> element
